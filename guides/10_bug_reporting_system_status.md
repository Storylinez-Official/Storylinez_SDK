# How to Report Bugs and Check System Status

## Overview
This tutorial explains how to report bugs you encounter while using Storylinez and how to check the system status to understand any ongoing issues. These tools help maintain platform quality and keep you informed about system health.

## Prerequisites
- You must be logged into your Storylinez account
- You should have specific details about any bugs you want to report

## Accessing System Tools

### 1. Finding System Tools in the Dashboard
1. Look at the left sidebar in your dashboard
2. At the bottom of the sidebar, you'll see a "System Tools" button with a gauge icon
3. Next to the gauge icon, there's a small colored dot indicating system health:
   - **Green dot**: System is healthy and operating normally
   - **Yellow/Amber dot**: System has warnings or degraded performance
   - **Red dot**: System has errors or significant issues
   - **Gray dot**: System status is unknown

### 2. Opening System Tools
1. Click on the "System Tools" button in the left sidebar
2. A system tools dialog will open with multiple tabs
3. You'll see tabs for "Status", "Bug Report", "History", and "Changelog"

## Checking System Status

### 1. Viewing Current System Status
1. Click on the "Status" tab (should be selected by default)
2. You'll see an overall system health percentage
3. Individual service statuses are displayed:
   - **API Server**: Core application programming interface
   - **Database**: Data storage and retrieval system
   - **File Storage**: Media and file management system
   - **Background Jobs**: Processing tasks and rendering
   - **External Services**: Third-party integrations

### 2. Understanding Status Indicators
- **Green/OK**: Service is operating normally
- **Yellow/Warning**: Service has minor issues but is functional
- **Red/Error**: Service has significant problems
- **Gray/Unknown**: Status cannot be determined

### 3. Refreshing Status Information
1. Click the "Refresh" button to get the latest status
2. Status information is automatically updated when you open the dialog
3. The colored dot in the sidebar reflects the overall system health

## Reporting Bugs

### 1. Starting a Bug Report
1. Click on the "Bug Report" tab in the system tools dialog
2. You'll see a form for describing the issue you encountered
3. There's a text area for entering your bug description

### 2. Writing an Effective Bug Report
Include the following information in your bug description:
- **What you were trying to do**: Specific action or task
- **What happened instead**: Describe the unexpected behavior
- **Steps to reproduce**: List the exact steps that led to the bug
- **Browser and device info**: This is automatically collected
- **Error messages**: Copy any error messages you saw
- **Screenshots**: Describe what was shown on screen

Example format:
```
I was trying to: Create a new video project
What happened: The page showed a loading spinner but never completed
Steps to reproduce:
1. Clicked "New Project" button
2. Selected video template
3. Clicked "Create Project"
4. Page got stuck loading

Error message: "Failed to initialize project"
```

### 3. Submitting the Bug Report
1. Write your detailed bug description in the text area
2. Click "Submit Bug Report" button
3. The system will automatically collect:
   - Your browser type and version
   - Current page URL
   - System performance data
   - Network connectivity info
   - Any JavaScript errors
4. You'll receive a confirmation that your report was submitted

### 4. What Happens After Submission
1. Your bug report is sent to the development team
2. It includes both your description and technical diagnostic data
3. The team will investigate and work on a fix
4. Critical bugs are prioritized for immediate attention

## Viewing Bug Report History

### 1. Accessing Your Previous Reports
1. Click on the "History" tab in the system tools dialog
2. You'll see a list of bug reports you've submitted previously
3. Each report shows:
   - Submission date and time
   - Brief description or title
   - Current status (if available)

### 2. Viewing Report Details
1. Click on any previous report to see full details
2. You can review what information was submitted
3. This helps avoid duplicate reports for the same issue

## Checking Platform Updates

### 1. Viewing Changelog
1. Click on the "Changelog" tab to see recent platform updates
2. You can filter between "Website" and "SDK" updates
3. Each changelog entry shows:
   - Version number
   - Release date
   - New features, improvements, and bug fixes
4. This helps you understand what changes might affect your workflow

## Best Practices for Bug Reporting

### 1. Before Reporting
- Check the system status first - the issue might be a known system problem
- Try refreshing the page or logging out and back in
- Check if the issue happens in different browsers
- Look at recent changelog entries for known issues

### 2. Writing Quality Reports
- Be specific and detailed in your descriptions
- Include exact error messages (copy and paste them)
- Mention what browser and device you're using
- Describe the impact on your work
- Include steps that someone else could follow to reproduce the issue

### 3. Follow-up
- Check the system status if you continue having issues
- Avoid submitting duplicate reports for the same problem
- Include additional information if you discover more details

## Troubleshooting Common Issues

### System Tools Won't Open
- Try refreshing the page
- Check your internet connection
- Clear browser cache and cookies
- Try a different browser

### Status Shows as Error
- This indicates known system issues
- Check the changelog for any maintenance announcements
- Wait a few minutes and refresh the status
- Consider postponing critical work until status improves

### Bug Report Won't Submit
- Check your internet connection
- Try submitting a shorter description
- Contact support directly via email if the form doesn't work

The system tools provide transparency about platform health and give you a direct way to help improve Storylinez by reporting issues you encounter.
